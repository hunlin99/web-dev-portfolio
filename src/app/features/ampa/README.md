# AMPA case study

Route: `/ampa`. Six sections tell one connected brand and UX story. Each section keeps its own HTML layout for independent customization.

- `ampa.content.ts`: project metadata, section navigation, user needs, three design principles, short brand rationales, palette, vendor decisions, journeys, and deliverables.
- `ampa.component.html`: context/challenge → user groups → cultural design system → UX decisions/flows → final mobile/responsive web work → outcomes/reflection.
- `ampa.component.css`: existing visual identity and responsive layouts, compact metadata row, and short visual annotations. Hero video and reduced-motion fallback are retained.
- `ampa.component.spec.ts`: route, six-section structure, retained legacy anchors, asset links, and contents navigation.

## Content mapping

The former strategy section is a short set of principles within Context. Brand Identity and Design System are merged, progressing from cultural references and logo exploration to the final logo/component board. Role-switching appears once beside its diagram; consumer/vendor screens appear together with task-specific annotations. Vendor listing and dashboard decisions use Problem → Decision → Design result. Final Product shows the existing desktop/tablet/phone website mockup. Outcomes lists deliverables and separates lessons and next steps from unverified impact.

Removed copy consists of repeated marketplace introductions, repeated role-switching explanations, verbose brand rationales, and separate constraints/benefits that overlapped with the decisions. No design assets were deleted. Existing `#strategy`, `#system`, and `#decisions` fragments remain as subsection anchors, while the contents links to six main sections.

## Evidence and gaps

The supplied cultural references, logo ideation, final brand board, full/mobile user flows, account-switch diagram, and consumer/vendor screens are retained. The device mockup provides existing responsive-web visual evidence. The page identifies design assumptions, illustrative dashboard numbers, and intended benefits; it claims no research validation, adoption, or measured improvement.

A verified interactive Figma prototype URL and detailed project timeline have not been supplied. The Afroidentity link remains labeled as a website, not a prototype. No guessed URL, dates, or additional screenshots are introduced. More detailed listing-setup wireframes could strengthen the progressive-disclosure example if supplied.

Sora and DM Sans describe the product system; the page retains the site's existing typography. The palette uses actual CSS colors. Two lossless WebP derivatives (`AMPA_w_device.webp` and `App-Switch-interface-flow.webp`) save approximately 1.77 MB combined against their PNG sources, retaining original pixel dimensions. Source PNGs remain available.

## Reading estimate

The six core sections contain 706 rendered English words, including headings, captions, palette labels, and the closing link; this excludes the hero, site navigation, contents, and text embedded in images. At 200–250 words/minute, reading takes approximately 2.8–3.5 minutes. Allow a separate 1.5–2 minutes for visual review: roughly 4.3–5.5 minutes overall. This is an estimate, not a measured user result.
